Engine States

ModState · ModSubState · PlayState

The three core script-facing classes — how mods build scriptable states and how gameplay is exposed to Lua / HScript.

All three are MusicBeatState / MusicBeatSubstate subclasses. State replacement hooks into MusicBeatState.switchState → ModState.resolveState and openSubState → ModSubState.resolveSubState.

ModState — scriptable state

A "scriptable state" modeled after Codename Engine. It loads an HScript/Lua file from data/states/<name> and hosts the static state-replacement system so mods can redirect built-in states (e.g. TitleState) to a scripted ModState.

}

ModSubState — scriptable substate

A scriptable substate (extends MusicBeatSubstate). Reuses ModState.substateReplacements. Its resolveSubState(original) swaps an already-instantiated FlxSubState for a ModSubState.
MemberTypeDescription
lastName · lastDataString · DynamicSame pattern as ModState.
dataDynamicCustom data injected as data.
new(_stateName, ?_data)—Stores name/data then super(lastName).
resolveSubState(original)FlxSubStateSwaps in a ModSubState when the active mod defines a replacement.

PlayState — gameplay state

The main gameplay state. Its public fields are the basis for nearly every Lua/HScript global reference (via PlayState.instance.xxx). It manually loads scripts/ and stages/<curStage> scripts; the parent adds data/states/PlayState/ & hscripts/PlayState/.
